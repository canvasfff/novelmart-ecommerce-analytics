# Olist 电商经营分析项目报告

## 一、项目背景

本项目基于巴西电商平台 Olist 公开的真实脱敏数据集，构建一套完整的电商经营分析平台。数据覆盖 2016-09 至 2018-10，包含订单、客户、卖家、商品、支付、评论、地理等 9 类核心业务数据。项目目标是：

1. 完成从原始 CSV 到清洗数据、MySQL 存储、Python 分析、可视化看板的完整数据链路；
2. 从真实数据中提炼可落地的经营洞察，覆盖销售、用户、商品、履约四大主题；
3. 形成一套可在面试中展示的综合数据分析项目。

## 三、数据清洗与特征工程

### 3.1 数据质量检查

- 客户、卖家、订单、明细、支付表无缺失值；
- 商品表 610 个商品缺失品类与文本/图片字段，统一归为 `unknown` 并使用中位数填充数值字段；
- 订单表物流时间存在合理缺失（未送达/未发货订单）；
- 评论表 88.3% 无标题、58.2% 无正文，属于真实评论数据常态，仅作缺失记录不删除；
- 原始评论表存在 827 条 `review_id` 重复，清洗时按主键去重。

### 3.2 外键完整性

- `orders.customer_id → customers`：通过
- `order_items.order_id → orders`：通过
- `order_items.product_id → products`：通过
- `order_items.seller_id → sellers`：通过
- `order_payments.order_id → orders`：通过
- `order_reviews.order_id → orders`：通过

### 3.3 特征工程

| 主题 | 衍生字段 |
|------|---------|
| 订单 | 支付总额、主支付方式、商品总额、运费总额、明细行数 |
| 物流 | 实际送达天数、预计送达天数、延迟天数、是否准时 |
| 商品 | 销量、订单数、商品销售额、运费、总营收、平均售价、评论数/评分 |
| 客户 | 首单时间、末单时间、有效订单数、累计支付、平均客单价、评论数/评分 |

### 4.5 品类与地域

- **销售额 Top3 品类**：health_beauty（9.14%）、watches_gifts（8.25%）、bed_bath_table（7.88%）；
- **州级集中度**：SP 州贡献 37.4% 营收，RJ、MG 紧随其后，三大州合计约 62.5%；
- **城市级**：圣保罗、里约热内卢、贝洛奥里藏特为 Top3 城市。

### 4.6 配送时效

- 平均送达 12.56 天，整体准时率 91.89%；
- SP 州平均 8.76 天、准时率 94.1%；北部/东北部州（如 PA、AM、AP）平均 20+ 天；
- 偏远地区物流时效是用户体验的主要短板。

## 五、高级分析

### 5.1 RFM 客户分群

基于唯一客户计算 Recency / Frequency / Monetary，并使用四分位法将客户分为 8 类：

| 客户分群 | 客户数 | 人均消费 |
|---------|--------|---------|
| 重要价值客户 | 12,428 | R$ 272.70 |
| 重要保持客户 | 11,815 | R$ 271.17 |
| 重要挽留客户 | 11,426 | R$ 266.32 |
| 重要发展客户 | 11,826 | R$ 260.38 |
| 一般保持客户 | 11,911 | R$ 64.36 |
| 一般挽留客户 | 12,343 | R$ 63.78 |
| 一般价值客户 | 11,341 | R$ 63.43 |
| 一般发展客户 | 11,900 | R$ 63.07 |

高价值客户约占总客户 13.1%，但人均消费是普通客户的 4 倍以上，是重点运营对象。

### 5.2 客户生命周期

| 阶段 | 客户数 | 说明 |
|------|--------|------|
| 活跃客户 | 17,837 | 最近 90 天有购买 |
| 沉默客户 | 19,717 | 90-180 天无购买 |
| 流失风险客户 | 35,521 | 180-365 天无购买 |
| 已流失客户 | 21,915 | 365 天以上无购买 |

超过 60% 客户处于流失风险及以上状态，需通过召回策略激活。

### 5.3 同期群留存

首购月份留存矩阵显示：Olist 客户次月留存率多在 0.2%-0.7% 之间，属于低频电商平台特征；2017 年 11 月（黑五）前后新客规模大，但长期留存仍需运营投入。

### 5.4 品类关联规则

仅 785 个订单包含 2 个及以上品类，说明 Olist 以单品类/低客单购买为主。挖掘出的高提升度组合包括 `home_confort → bed_bath_table`（Lift 1.13）等，可作为捆绑促销参考，但整体交叉销售空间有限。

### 5.5 销售预测

使用 3 个月移动平均与指数平滑对月度营收建模，2018 年 8 月实际营收约 R$ 99.7 万，模型指数平滑值 R$ 103.6 万，拟合趋势合理。简单下月预测（最近 3 月均值）约 R$ 67.9 万（9 月数据不完整所致）。

### 5.6 配送履约

各州准时率从 76%（AL）到 97%（RO）不等；SP 等核心州时效最优，偏远州需优化物流网络或延长承诺时效。

## 六、SQL 数据库设计

### 6.1 数据库结构

- 数据库：`olist_ecommerce`
- 9 张核心业务表 + 客户聚合表
- 外键：订单→客户、明细→订单/商品/卖家、支付→订单、评论→订单
- 20+ 个二级索引覆盖高频过滤字段（时间、状态、州、品类）

### 6.2 视图与存储过程

- `v_order_facts`：有效订单事实宽表
- `v_product_performance`：商品销售表现
- `v_customer_summary`：客户价值汇总
- `sp_calculate_rfm()`：MySQL 版 RFM 分群存储过程
- 触发器：校验评论评分 1-5

### 6.3 SQL 分析能力

提供 40+ 条业务 SQL，包括月度趋势、品类排行、州销售、支付分布、评分分布、复购率、窗口函数环比、配送时效、RFM 调用等，覆盖 CRUD 全场景。

## 八、业务洞察总结

1. **营收集中**：SP/RJ/MG 三州贡献约 62.5% 营收，核心市场应重点投入；
2. **支付优化**：信用卡主导，可强化分期营销；boleto 占比高，需关注支付成功率；
3. **用户体验**：平均 4.07 分、76.7% 好评，但 1 星差评占比 11.8%，需重点分析差评订单；
4. **物流短板**：偏远州送达 20+ 天，准时率低于 85%，建议优化仓配布局；
5. **客户价值分层**：重要价值客户人均消费高，可设计专属权益提升 LTV；
6. **低频特征**：复购与多品类购物篮比例低，需要通过会员体系和交叉推荐提升频次；
7. **品类机会**：health_beauty、watches_gifts 销售领先，可重点选品与备货；
8. **季节性**：11 月（黑五）订单量显著冲高，应提前做好库存与物流准备。
