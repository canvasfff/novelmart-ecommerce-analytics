### 第6题：你提到了 RFM 分析，能解释一下什么是 RFM 吗？在这个项目中怎么用的？

**回答：**
RFM是客户价值分析的经典模型，三个字母分别代表：
- **R（Recency）**：最近一次消费距今天数，越短说明客户越活跃
- **F（Frequency）**：一段时间内的消费频次，越高越忠诚
- **M（Monetary）**：消费总金额，越高价值越大

我的做法是：以2026年7月31日为基准日，计算每个用户的R/F/M值，然后用四分位数分别打1-4分，R分+ F分+ M分得到综合RFM分，再分成8类：
- 重要价值客户（R高F高M高）：平台核心用户，占比约27%
- 重要发展客户（R高F低M高）：有消费能力但频次低，需刺激复购
- 重要挽留客户（R低F高M高）：曾经高价值但很久没来，需发优惠券召回
- 一般价值客户（R高F高M低）：活跃但客单价低，可做升级引导

这个分析直接指导了我在项目报告中提出的"对流失高价值用户定向发券"的商业建议。

### 第13题：同期群分析（Cohort Analysis）你是怎么做的？

**回答：**
同期群分析是用来衡量用户留存率的。我的做法是：
1. 把用户按注册月份分成不同的同期群（cohort），比如2024年1月注册的一组、2024年2月的一组...
2. 然后看每个同期群在注册后的第1个月、第2个月...第N个月，分别有多少比例的人还有下单行为
3. 用Pandas的 `pivot_table` 做了一个"同期群×时间偏移"的留存率矩阵

核心代码逻辑：
```python
# 给每个用户打上注册月份标签
users['cohort_month'] = users['registration_date'].dt.to_period('M')
# 给每笔订单打上距离注册月的偏移
orders_with_cohort = orders.merge(users[['user_id', 'cohort_month']], on='user_id')
orders_with_cohort['order_month'] = orders_with_cohort['order_date'].dt.to_period('M')
orders_with_cohort['period_offset'] = (orders_with_cohort['order_month'] - orders_with_cohort['cohort_month']).apply(lambda x: x.n)
# 透视: 行=同期群, 列=偏移月份, 值=活跃用户数
retention = orders_with_cohort.pivot_table(index='cohort_month', columns='period_offset', values='user_id', aggfunc='nunique')
# 第一期=100%，后续/第一期得到留存率
retention_pct = retention.div(retention[0], axis=0)
```

当前数据下注册后首月平均留存率约28.8%，第3个月约23.4%，留存随月份逐步衰减，符合用户生命周期的一般规律。真实业务里留存分析通常聚焦"注册后首单转化"与"次月复购"两个漏斗，我在这里演示了同期群×时间偏移的留存矩阵构建方法。

### 第14题：解释一下商品关联分析（Market Basket Analysis）你是怎么做的？

**回答：**
我没有用Apriori算法库，而是用Pandas手工实现了核心逻辑——因为面试更看重你对原理的理解。

做法：先按order_id聚合每个订单买了哪些品类（subcategory），然后两两配对生成"品类对"，统计：

- **支持度（Support）**：A和B同时出现的订单数 / 总订单数
- **置信度（Confidence）**：买了A的订单中也买了B的比例
- **提升度（Lift）**：Confidence / B的自然购买概率，Lift>1说明正相关

比如当前数据中最强的子类别对「书法字帖」与「婴儿床」Lift≈1.38，说明二者共现概率是随机水平下的1.38倍；大多数品类对的Lift在1.1-1.4之间，Lift接近1说明两品类相互独立。需要说明的是，品类级的关联整体偏弱——若细化到商品级、或改用订单级购物篮（而非子类别级），共现结构会更显著，这也是关联分析落地时通常的做法。

这个分析结果可以用来做推荐系统——用户买了手机就推荐手机壳——也可以指导促销组合设计。

解决方案：
1. **统一口径**：商品销量和评分在订单/评论对账后用真实聚合回填覆盖，保证商品表与明细、评论完全一致
2. **全量参照完整性校验**：6项外键检查（orders→users、order_items→orders/products、reviews→三表）全部0孤儿记录
3. **金额三字段对账**：订单的 total_amount / discount_amount / actual_amount 与明细行总额逐单核对，含运费口径一致
4. **双路径数字对齐**：SQL 侧与 Python 侧采用同一折扣口径（数量×单价×(1-折扣)），两套分析结果相互印证

最终跨表完全对账，SQL 与 Python 两套分析路径的数字保持一致，做groupby分析时能看到差异化的趋势和合理的分布。

### 第17题：SQL 的窗口函数你用过哪些？能举例子吗？

**回答：**
在项目中用了三个窗口函数场景：

**ROW_NUMBER / RANK / DENSE_RANK：** 各品类内按销售额排名（项目中的B-12查询）：
```sql
SELECT p.category, p.product_name,
       ROUND(SUM(oi.quantity * oi.unit_price * (1 - oi.discount)), 2) AS revenue,
       DENSE_RANK() OVER (PARTITION BY p.category
                          ORDER BY SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) DESC) AS rank_in_category
FROM products p
JOIN order_items oi ON p.product_id = oi.product_id
GROUP BY p.category, p.product_name;
```

**LAG / LEAD：** 计算月度销售额的环比增长率：
```sql
SELECT month, actual_revenue,
       LAG(actual_revenue) OVER (ORDER BY month) AS prev_month_revenue,
       ROUND((actual_revenue - LAG(actual_revenue) OVER (ORDER BY month)) 
             / LAG(actual_revenue) OVER (ORDER BY month) * 100, 2) AS mom_growth_pct
FROM v_monthly_sales;
```

**SUM() OVER()：** 计算累计销售额和累计占比（帕累托分析）：
```sql
SELECT product_name, sales_count,
       SUM(sales_count) OVER (ORDER BY sales_count DESC) AS cumulative_sales,
       ROUND(SUM(sales_count) OVER (ORDER BY sales_count DESC) 
             / SUM(sales_count) OVER () * 100, 2) AS cumulative_pct
FROM products;
```

窗口函数最大的好处是不需要子查询或临时表就能在每一行上做跨行计算。

### 第18题：如果数据量从30万变成3000万，你的方案需要做哪些调整？

**回答：**
30万到3000万是100倍的量级跨越，需要多方面的调整：

**存储层**：MySQL单表扛不住，考虑分区表（按月份分区orders表），或者迁移到ClickHouse/Doris这类OLAP引擎。

**计算层**：Pandas单机加载3000万行会OOM，改用分块读取`pd.read_csv(chunksize=100000)`，或者用Dask/Polars替代Pandas做分布式计算。

**查询层**：SQL中避免全表扫描，所有分析查询必须走索引。复杂聚合考虑物化视图或定时预计算。

**可视化层**：Tableau连明细数据会很慢，应该连聚合后的数据集（数据提取），或者预先在数据库里跑好聚合SQL，Tableau只连结果表。

思路是一样的，只是工具选型和优化策略要升级。

### 第19题：你对数据分析的理解是什么？一个完整的数据分析流程是怎样的？

**回答：**
我觉得数据分析不是"跑个数给老板看"，而是"从数据中找到能指导行动的洞察"。

完整流程分六步：
1. **明确问题**：业务方到底想解决什么？比如"为什么最近销售额下降"而不是"帮我拉个数据"
2. **数据采集**：从数据库/日志/API等渠道获取原始数据
3. **数据清洗**：缺失值处理、异常检测、格式标准化——这个过程通常占60%时间
4. **数据分析**：描述性统计→探索性分析→深度挖掘（RFM、同期群、相关性分析等）
5. **可视化呈现**：把分析结果用图表讲成故事，Tableau/Matplotlib都是工具
6. **输出建议**：给出可落地的业务建议，而不是只给数据——"建议对流失高价值用户发放满200减50的召回券" > "流失率15%"

我这个项目基本就是按照这个流程走的。

我这个项目就是刻意训练了这三种能力——技术实现（Python+SQL+Tableau）、业务思考（RFM分群→营销策略）、文档表达（完整的项目报告）。
